# 下限

「做高级一点」没法检查。能检查的是计划和像素。

半成品通常是这样的：底很干净，字漂进来，合成一个图形，角落里一个手画的圆当标记，字体是系统里碰巧有的，句子是编的。每一帧都没有报错。它只是没做完。

## 计划闸门

`npm run mfl -- brand <入口>` 读入口旁边的 `shot-list.md`、`copy.md`、`assets.md`。三份都要在，而且不能留着「待填」。

段数、时刻表、自检条数不在闸门里。那些写在 [shot-list.md](shot-list.md)，会改。闸门只确认计划文件写过了。

cue 要是画面上真有的事件。登记几个没有画面的名字，画面闸门仍然会失败。

不要去数 `spring()` 写了几次。帧函数是纯函数，调用次数垫得上去，内容垫不上去。

## 画面闸门

`npm run mfl -- frames <入口>` 按大约每秒 5 帧、缩小后的 RGBA 来量。底色取合成的 `background`。很淡的格子和颗粒不会被算进覆盖率，所以不能靠把底纹调浓过关。

| 量的 | 参考片 | 下限 |
| --- | --- | --- |
| 中位覆盖率 | 0.097 | ≥ 0.06 |
| 中位细节（相邻像素亮度差得开） | 0.012 | ≥ 0.008 |
| 中位运动 | 0.011 | ≥ 0.007 |
| 最空一段的中位覆盖率 | 0.051 | ≥ 0.035 |
| 近乎不动的最长时间 | 2.2 秒 | ≤ 2.5 秒 |

这些数是这个采样方式下的下限，卡在空画面之上、参考片之下。换分辨率或换阈值，数字会变，规矩不变：空的不过，有产品在干活的过。参考片的数会随画面改动，改完要重跑 `frames`，把表更新成新的测量。

失败时不要把字放大来凑。把产品放到画面上，让一段里一直有东西在动。

## 排版

`check` 的 error 为零。字被挡住、字太小、字出安全区，都先改摆位。细则在 [layout.md](layout.md)。

## 和参考片比

渲染 `examples/brand` 的联系表，再渲染自己的，并排看完成度，不看像不像：

1. 多少帧能看出产品在干什么。起幅和落幅可以稀一点。
2. 落幅之外，有多少帧几乎是底。
3. 换掉产品名之后，段数、强调色、落幅、手法是不是还和参考片对得上。对得上，创作还没开始。

明显更空，就还没做完。为了靠近参考片的覆盖率去加卡片、长条、角标，也还没做完。下限挡住空画面，不是凑分的目标。过了就停。

## 手法和转场

相邻的同类元素不用同一种入场。入场从这段的动词来。[recipes.md](recipes.md) 演示一种动作怎么写成代码，不是要凑齐的清单。

转场至少两种不是「整段透明度交叉淡化」的。这两种写进分镜，用这支片子的动词命名。交叉淡化最多用一次。

全片有一个物件跨过至少一条段界。角落标记不算。

## 产品

从简介里列出这支片子要演的具体行为，分到段里。少了或多了都按事情本身来。某一段没有产品行为，它只能是起幅或落幅。

每一句画面文字都能指回 `copy.md` 的出处。必须出现的卖点，按原文出现。
